# 揪好森 LINE 官方帳號架構與操作手冊

更新日期：2026-10-17

## 一句話理解

客人把 LINE 當成單純的聊天窗口；LINE 把訊息交給 Cloudflare，Cloudflare 先查即時檔期或揪好森核定知識庫，再用親切的客服小編口吻回覆。遇到需要老闆決定的事情，系統會先用自然口吻告知客人「小編會再跟老闆確認」，暫停該客人的後續自動回覆，並私下通知已綁定的管理員。

## 系統怎麼運作

```text
客人傳訊息
   ↓
LINE 官方帳號
   ↓  Webhook（簽章驗證）
Cloudflare Pages Function
   ├─ 檔期問題 → 私密 Google Calendar 來源 → 只整理「可預約／可候補／已預訂／不可預訂」
   ├─ 一般問題 → D1 知識庫（62 筆核定答案）
   ├─ 不在固定答案內的安全問題 → Cloudflare Workers AI 組織語句
   ├─ 對話狀態／暫停／恢復 → Workers KV
   └─ 特殊需求／預訂／付款 → 暫停並通知管理員
   ↓
LINE Messaging API Reply API
   ↓
客人在原本聊天室收到回覆
```

目前使用的固定 Webhook 網址是：

`https://camp.8-ways.com/api/line-webhook`

不要改成每次部署都會變動的 `xxxx.pages.dev` 預覽網址。

## 各系統的工作

### LINE 官方帳號

- 提供客人加入好友與聊天的入口。
- 將收到的訊息以 Webhook 事件送到 Cloudflare。
- 將 Cloudflare 產生的文字送回同一位客人。
- 不使用 LINE 內建 AI，也不建立圖文選單、點數或複雜商店功能。
- 回應設定維持「聊天開啟、Webhook 開啟、加入好友歡迎訊息關閉、手動聊天」。

### Cloudflare Pages Function

- 驗證 LINE 簽章，避免外人偽造請求。
- 判斷問題屬於露營車或露營區。
- 判斷是一般資訊、即時檔期，還是必須暫停的決策問題。
- 組成回覆並呼叫 LINE Reply API。
- 這是整個系統的中樞。

### Cloudflare D1

- D1 是可查詢的資料庫，不是檔案硬碟。
- 目前收錄露營車 32 筆、露營區 30 筆，共 62 筆核定知識。
- 人可以閱讀與維護的母檔放在：
  - `knowledge/line/campervan.md`
  - `knowledge/line/campsite.md`
  - `knowledge/line/operations.md`
- Markdown 更新後，會產生 SQL、測試，再同步到 D1。

### Cloudflare Workers KV

- 保存每位客人的近期對話脈絡、服務類別與暫停狀態。
- 保存事件去重資料，避免同一則 Webhook 重複回覆。
- 保存管理員綁定，以及「管理員恢復」代碼與客人的對應。
- 對話狀態目前保留 90 天；事件去重資料保留 1 天。

### Cloudflare Workers AI

- 只處理沒有命中固定知識、但仍可安全回答的一般問題。
- 它不是 OpenAI API，不需要 OpenAI API Key，也不會扣 ChatGPT／Codex 額度。
- 重要事實仍以 D1 與即時檔期為主，AI 只負責自然地組織文字。
- 如果無法安全判斷，系統不亂猜，會暫停並通知管理員。

### Google Calendar 檔期來源

- 露營車與露營區使用不同的私密行事曆來源。
- 私密網址保存在 Cloudflare Secret，不寫在網站原始碼或公開資料庫。
- 客人只會看到日期狀態，不會看到訂房姓名、電話、備註或行事曆標題。

### R2 有沒有使用

目前沒有使用 R2。Cloudflare 沒有叫「R1」的這個知識庫元件；目前實際使用的是 D1（問答資料）、KV（對話狀態）與 Workers AI（安全的一般語句整理）。若未來要保存大量圖片、語音或附件，才可能加入 R2。

## 哪些問題會自動回答

- 官網已有答案的一般資訊。
- 房型、床型、人數、設備、交通、寵物、餐點、衛浴、教學、駕照、價格說明等。
- 露營車單一日期：會說明最低 3 天 2 夜並追問取車、還車日期。
- 露營車完整日期範圍：會讀取即時行事曆後回覆狀態。
- 露營區日期與指定房型：會讀取熱氣球房與雲朵房即時狀態。
- 每則資訊回覆都要附最相關的網站頁面。

## 哪些問題會暫停並通知管理員

- 客人明確說要正式預訂、訂房、訂車或保留檔期。
- 客人表示已付款、已匯款，或傳送付款／其他圖片。
- 折扣、殺價、額外優惠。
- 提早入住、延後退房、提早交車、延後還車或異地還車。
- 長租、包月、企業合作、商業拍攝、大型活動、發票統編等特殊需求。
- 即時檔期來源暫時讀不到。
- 問題不在核定知識內，或產生的內容可能越權承諾。

客人會看到的說法不會出現「AI」、「機器人」、「轉人工」或「自動回覆」，只會自然地說：

> 謝謝您跟小編說明需求～這部分需要再確認，小編會先幫您詢問老闆，確認後再回覆您。

## 管理員綁定是什麼

先分清楚三個名稱：

| 名稱 | 用途 | 在哪裡操作 |
|---|---|---|
| LINE 後台「權限管理」 | 讓某個人可以登入 Official Account Manager 管理帳號 | LINE 官方帳號後台 |
| 本系統「管理員綁定」 | 指定哪一個私人 LINE 接收待確認通知 | 私人 LINE 對官方帳號傳送綁定指令 |
| 本系統「管理員恢復」 | 人工處理完成後，只解除某一位客人的暫停 | 已綁定的私人 LINE 傳送恢復指令 |

三者互不等同。只做 LINE 後台權限管理，不會自動收到本系統的待確認通知；只做本系統管理員綁定，也不會因此取得 LINE 後台登入權限。

### 功能

把「哪一個私人 LINE 帳號要接收待確認通知」告訴系統。這不是 LINE Official Account Manager 的權限管理，也不會讓客人看到任何管理員資料。

### 第一次設定

用要接收通知的私人 LINE 帳號，對官方帳號傳送：

`管理員綁定 <一次性驗證碼>`

系統會：

1. 比對保存在 Cloudflare Secret 的驗證碼。
2. 將該私人 LINE 的 User ID 寫入 KV。
3. 回覆「管理員通知已啟用」。
4. 之後需要確認的案件，就會推送到這個私人 LINE。

### 注意事項

- 驗證碼視同密碼，不要放在網站、貼文、客服話術或截圖中。
- 正常情況只綁定一次，不用每天重綁。
- 若驗證碼外流，應更換 Cloudflare Secret。
- 若要改由另一個私人 LINE 接收通知，使用新的管理員帳號重新綁定即可。

## 管理員恢復是什麼

### 為什麼需要它

當客人進入需確認狀態後，系統會暫停該客人的自動回覆，避免老闆與系統同時回答、重複承諾或在付款階段出錯。

管理員會收到類似通知：

```text
【LINE 待確認】
客人：○○○
服務：露營區
原因：客人準備預訂
客人訊息：我想預訂……
請到 LINE 官方帳號聊天室接續回覆。
處理完成後，請傳送：管理員恢復 <恢復代碼>
```

### 正確操作順序

1. 管理員先到官方帳號聊天室查看完整對話。
2. 人工確認檔期、價格、特殊需求或款項。
3. 在官方帳號後台直接回覆客人需要的內容。
4. 確定這一階段處理完成後，用已綁定的私人 LINE 傳送：

   `管理員恢復 <恢復代碼>`

5. 系統會解除該客人的暫停；從客人下一則訊息開始恢復一般自動回覆。

### 「恢復」不會做的事

- 不會替管理員回覆上一則待處理訊息。
- 不會自動告訴客人「已恢復」。
- 不會確認付款或建立訂單。
- 只解除該客人的暫停狀態。

## 每天實際怎麼操作

一般情況不用操作 Cloudflare，也不用登入程式後台：

1. 一般問題由系統直接回答。
2. 即時檔期由系統查詢後回答。
3. 手機收到「LINE 待確認」時，再進官方帳號聊天室處理。
4. 處理完傳送「管理員恢復 <恢復代碼>」。

## 官方帳號門面建議值

- 大頭照：使用揪好森官方方形 Logo，不使用房間或露營車照片，避免縮成小圓形後認不出品牌。
- 狀態消息：`露營區／露營車｜檔期・房型・租車詢問`
- 聯絡電話：`0911-252-302`
- 露營區網站：`https://camp.8-ways.com/`
- 露營車網站：`https://van.joyforest.tw/`
- 背景圖片：`assets/images/line/joyforest-line-cover-2x1.png`
- 快捷按鍵：只保留必選的「聊天」；不額外建立圖文選單、集點、優惠券或商店入口。
- 付款方式：可標示「銀行轉帳（確認檔期與金額後提供資料）」，但不要啟用 LINE Pay 或讓系統自行確認款項。
- 地址：公開資訊只寫「桃園楊梅」；完整進場資訊仍由確認預訂後提供。

LINE 已公告商業簡介背景圖片將改為 2:1 顯示，因此背景圖已另外準備 2:1 安全版，Logo 與文字都放在中央安全區，避免上下裁切。

## 知識怎麼學習與更新

系統不會把客人的每句話直接當成新知識，避免錯誤、玩笑、個資或特殊個案污染客服答案。更新採受控流程：

1. 由管理員請 Codex 檢查最近一週或指定期間的新問題。
2. 去除姓名、電話、付款、行程備註等個資。
3. 把可重複使用的正確答案寫回 Markdown 母檔。
4. 產生 D1 SQL。
5. 執行自動測試與人工語氣檢查。
6. 同步 D1 並部署 Cloudflare。
7. 用 LINE 做一輪實機冒煙測試。

可以直接對 Codex 下指令：

> 請檢查最近 7 天 LINE 官方帳號的新問題，整理沒有收錄的常見問法，去除個資後更新露營車與露營區知識庫；完成測試、同步 D1、部署，最後列出新增與修改內容。不要直接把特殊個案當成通用規則。

## 費用與額度

- 不需要 OpenAI API Key，也不會使用 OpenAI API 額度。
- LINE 官方帳號目前是輕用量方案。LINE 官方資料顯示輕用量月費為 0 元、每月 200 則免費訊息；Messaging API 的 Reply API 不計入方案訊息數，所以一般客問客答不會消耗這 200 則：<https://developers.line.biz/en/tips/2026/05/28/how-to-count-messages/>
- 需要管理員確認時，系統是用 Push API 主動通知已綁定的私人 LINE；Push API 會計入方案訊息數。也就是說，每一筆「待確認通知」通常會使用 1 則額度，公開群發貼文／訊息也要另外計算。方案仍以 LINE 最新公告為準：<https://tw.linebiz.com/column/LINEOA-2026-Price-Plan/>
- Cloudflare Workers AI 免費額度目前為每日 10,000 Neurons；超過免費額度才需要評估 Workers Paid。官方說明：<https://developers.cloudflare.com/workers-ai/platform/pricing/>
- D1 Free 目前含每日 500 萬列讀取、10 萬列寫入與總計 5 GB 儲存：<https://developers.cloudflare.com/d1/platform/pricing/>
- Workers KV Free 目前含每日 10 萬次讀取、1,000 次寫入與 1 GB 儲存：<https://developers.cloudflare.com/kv/platform/pricing/>
- 以目前一個露營區／露營車官方帳號的詢問量，D1 與 KV 距離免費上限很遠；主要需要觀察的是 Workers AI 每日用量與 LINE 方案訊息數。固定知識命中率越高，AI 用量越低。

## 發生問題時先檢查

1. LINE Developers 的 Use webhook 是否開啟。
2. Webhook URL 是否仍是固定正式網址。
3. LINE Developers 的 Verify 是否顯示 Success。
4. LINE Official Account Manager 是否為「聊天開啟、Webhook 開啟、手動聊天」。
5. Cloudflare 最新 Production 部署是否 Active。
6. D1 是否仍有 62 筆啟用知識。
7. 私密行事曆 Secret 是否存在且可讀。
8. 若只有某位客人沒回覆，先確認是否正處於「待確認暫停」，不要直接重設整個系統。

## 安全原則

- 不把 LINE Channel Secret、Access Token、管理員驗證碼、私人行事曆網址寫入 Git 或文件。
- 不在客人回覆中顯示其他客人的姓名、電話、訂房標題或備註。
- 不由系統自行確認付款、承諾折扣或完成正式預訂。
- 修改知識後一定先測試再部署。
- 若看到不確定的答案，先暫停該客人並修正知識，不要讓錯誤答案持續擴散。
